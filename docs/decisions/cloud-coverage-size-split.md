## 1. 问题：云量在偷偷改云的大小

旧实现（2026-10-25 起）：

```glsl
coverage  = sat(weather.r * 云量滑条)
threshold = mix(0.62, 0.14, pow(coverage, 0.8))     // ← 云量进了阈值
density   = sat(remap(eroded, threshold, threshold + edge)) * heightGradient
```

阈值是"噪声值的切割线"：抬高它等于把**每一朵**云的边界往里削一圈 ⇒ 滑条一动，
云同时变少、变小。用户报的"云量也控制云大小"就是这个。

量化（`--model v5top` 俯视密度切片，18.8 m/px；covered = R>0 的面积占比，
scale = 连续密度场自相关半宽）：

| 云量 | covered | scaleX | 说明 |
| --- | --- | --- | --- |
| 0.48 | 97.8% | 15 px | 旧：几乎全遮 |
| 0.28 | 91.8% | 14 px | 旧：面积只掉 6%，**云被削小** |

也就是说旧滑条几乎不控制"多少"，主要在控制"每朵多瘦"。

## 2. 拆法：云量 → 存在性遮罩，阈值改成常数

```glsl
presT    = sat((云量 - 0.10) / 0.80)
presCut  = (1 - presT)^5                             // 分布遮罩的切割线
presence = smoothstep(presCut - 0.10, presCut + 0.10, weather.r)
if (presence <= 0.002) return;                       // 早退（也省掉整条密度链）
...
threshold = 0.41                                     // 常数，与云量无关
density  *= presence;
```

曲线是**按旧实现的"云量→天空被遮比例"反解**的，不是拍脑袋（两层证据）：
① 天气图 R 分布（`--dump-atlas` 导 512²/1920×1080 RGBA32F 后统计）：
P(R>0.20)=0.972 / 0.40→0.864 / 0.50→0.757 / 0.60→0.612 / 0.70→0.456 / 0.90→0.177。
② 旧构建实测（`--model v5top`，R>0 面积占比）：
云量 0.10→**0.8%**、0.19→**75.8%**、0.30→93.9%、0.48→97.8%、0.90→99.6%
—— 旧滑条几乎是开关（全剧变集中在 0.10~0.20），而存量存档正好是 0.19。
`(1-u)^5` 拟合这五点：0.10→1.00(≈8%)、0.19→0.55(≈74%)、0.30→0.24(≈96%)、0.48→0.04(≈99.6%)。

⚠ 下限只能到 ≈8%：天气图本身有 13% 面积饱和到 1.0，presence 再怎么抬也遮不掉 ⇒
"万里无云"要做到得改烘焙增益（未做）。

改后：

| 云量 | covered（新） | covered（旧） | scaleX（新/旧） |
| --- | --- | --- | --- |
| 0.19（存量存档） | 60% | 75.8% | 7 / 5 px |
| 0.48 | 99.7% | 97.8% | 7 / — |

（新覆盖率略低、每朵更完整：阈值是常数 0.41，不再在低覆盖区被抬到 0.53~0.62。）

## 3. 云的大小：方向反转放在 UI，**不能放在着色器**（柱子事故）

`cloudParams3.z` 存的是 **noiseScale**，而基座噪声的世界周期是 `HP_BASE_TILE / noiseScale`
⇒ **值越大云越小**。2026-10-28 先在着色器里翻成 `0.55²/size`，结果：

> 用户存档 `cloudSize = 1.45` ⇒ 旧语义下格胞 **460 格**（层厚 2080 里 4.5 个，正常），
> 翻转后变成 **3196 格 > 1.5×层厚** ⇒ 层内不到一个格胞、密度沿 y 恒定 ⇒ **云被竖向
> 拉成柱子/板**（实机反馈"云被拉伸成柱状"）。

修法：
1. 着色器恢复原语义 `hp.noiseScale = max(cloudParams3.z, 0.05)`（老存档逐位不变）；
2. **方向反转改在 UI**：滑条显示 `0.55 / 存档值`（"云的大小倍率"，越大云越大）；
3. 核心加**物理钳制**（`cloud_v5_core.glsl` 的 `minNoiseScale`）：
   格胞 = (BASE_TILE/noiseScale)/12 必须 ≤ 层厚/2 ⇒ `noiseScale ≥ HP_BASE_TILE/(6·slabH)`。
   层厚 2080 时下限 0.64，与存量值 1.45 不冲突；层薄时自动兜住，不可能再出柱子。

结论：**"云的大小"调到极限也受层厚约束** —— 想要更大的云，先把云层厚度加大（物理上就是
需要更高的云层才装得下更大的格胞）。

## 4. 天气图 1024² → 512²

- 游戏端 `CLOUD_V4_ATLAS_SIZE = 512u`：RGBA16F 8 MB → 2 MB，烘焙耗时 1/4。
- 天气图的职责已经变了：现在只决定"哪片区域有云"（云体形状全由 3D base 噪声 + 常数阈值
  决定），512²（187.5 m/texel）远超需要。
- 烘焙器同步砍掉最细一档倍频 f=16（512² 下只有 4 texel/格胞 ⇒ 必出 4×4 方块阵列，
  这是 2026-10-27 第 4 修的历史结论），权重比例分给 f=2/4/8：0.22/0.28/0.30/0.20 →
  0.275/0.35/0.375。实测 R 通道均值仍是 0.661（旧 0.66），标定没跑。
- **预览器也改成 512²**：以前是 1920×1080（非正方形），等于把天气场沿 Z 拉长 1.78×，
  预览和游戏在看两张不同的天气图。

## 5. 3D 噪声 mip 链（参考的 mipOffset 终于有效）

`CLOUD_V4_BASE_MIPS = CLOUD_V4_WORLEY_MIPS = 4`：base 128³ → 128/64/32/16，
worley 64³ → 64/32/16/8，`vkCmdBlitImage` 逐级 box 下采，采样器 `maxLod` 放开到 3。

- 顺带修一处分区布局：v5 烘焙是 storage 写（描述符声明 GENERAL），而烘焙前那段把三张图
  转到了 SHADER_READ_ONLY —— 现在补了一次 R/O → GENERAL。
- 代价：+2 MB 显存；外观代价实测 mean 0.60/255、p99 8.0（<1% 像素差 >8），几乎不可见。
- **收益在本机测不出来**：把光步 LOD 固定成 3 与"0..3 渐变"交替跑 4 轮（150 帧/轮），
  3908 ms vs 3840 ms = **1.7%，在噪声内**。8 MB 的 128³ 本来就躺在 L2 里，带宽不是瓶颈。
  保留它的理由是**结构性对齐**（参考就是靠这条 mipOffset 设计的）以及在 L2 更小的卡上
  才是真收益 —— 想验证必须实机跑帧率。

## 8. 2026-11-01 反转：常数阈值退役，覆盖率重新耦合阈值（逐柱，非全局）

用户报"体积云说不上来的怪"。复现（`--model v5 --game-save`，1280×720）：滑块 0.48 下
整屏一块均匀灰毯，无积云团块、无蓝天间隙；v5top 俯视切片被遮 ~85%（本档语义应为
"滑块 ≈ 被遮比例"）。v5slice 竖切：云底/云顶整条剖面等高（薄饼）。

### 根因就是 §2 的交易本身

§2 把阈值改常数换掉了"云量偷偷改云大小"，但保留下来的旧曲线意味着
**0.48 → 99.7% 被遮**——覆盖率滑条在常用区间（0.3~0.9）几乎不改变天空，
滑条只调浓度。常数阈值 0.41 + base 场均值 ~0.58 ⇒ 全场大面积过阈。

### 为什么逐柱耦合没有请回 §1 的事故

§1 的事故是**全局**抬阈值 ⇒ 每朵云的边界统一往里削。现在阈值 =
`mix(0.85, 0.30, sat(coverage × 1.45))`，coverage 是**逐柱**的
`weather.r × 滑块 × covMapScale`：湿区核心阈值低、云保持完整尺寸；
干缘阈值高、消散成絮。云的"大小"仍由 base 3D 噪声 + noiseScale 决定（§3 语义未动），
与滑条解耦的保证不变。

### 标定（v5top，R>0.1 = any / R>0.4 = opaque）

| 滑块 | any | opaque | 期望语义 |
| --- | --- | --- | --- |
| 0.20 | 29.5% | 9.5% | 稀疏 |
| 0.48 | 75.8% | 58.2% | 破云（约半边天） |
| 0.90 | 93.8% | 88.7% | 近阴天 |

GAIN=1.45 补偿天气图 R 均值 0.66 导致的高端饱和（无增益时 0.9 只盖 52%）。
 Rain 强制 0.98 → 阈值压到 ~0.33 → 近全覆盖 ✓。

### 同轮：云顶逐柱变化（weather.a）

烘焙器 `hpRenderWeather` 的 A 通道原先写死 0.5（纯浪费）。现写低频 value 噪声
（~24 km + ~12 km 两档）作云顶高度代理；密度侧把全天空同一条顶线
`1-smoothstep(0.82,1.0,h)` 换成 `topCut = mix(0.80, 1.30, weather.a)` 的逐柱截断。
旧资产（a=0.5）退化为 topCut=1.05，与旧行为几乎一致，热重载窗口不破相。

### 量化收益

- v5top 自相关半宽比（各向异性）：2.28 → **1.62**（特征尺度 430 m → 240 m，积云量级）。
- 竖切：密度从只占 h∈[0.18,0.77] 变为填满全层且顶界逐柱起伏。
- 性能：干柱在 simple 采样即早退（2 次采样 vs 命中路径 3 次+光步），
  云 pass 净成本预期下降（改前基线 0.13~0.14 ms @707×376，实机以 PERF L10 `cloud=` 为准）。

### 部署

`volumetric_clouds_v5.comp.spv` 热重载即时生效；
**`cloud_v5_noise.comp.spv`（烘焙器）必须重启游戏**才会按新天气图重烘（A 通道）。

⚠ 用户侧旋钮语义变化：`covMapScale`（GUI"覆盖映射倍率"，cloudHp[12]）旧模型里几乎
是 no-op（只进密度调光 0.65~0.70 一项），新模型里**直接 × coverage 进阈值**。
存量存档里有设成 3.0 的（补偿旧坏行为的遗留），等效把云量滑条放大 3 档；
要"滑块=被遮比例"的标定语义应设回 1.0。
